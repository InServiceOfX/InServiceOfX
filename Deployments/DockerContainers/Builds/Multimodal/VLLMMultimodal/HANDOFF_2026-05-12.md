### Rust Postgres Vector Store

Added:

- `RustLibraries/vector_store/`

Purpose:

- Persist document/page metadata and ColQwen page embeddings in PostgreSQL from
  Rust, following the GrokiCAD `sqlx` style.
- ColQwen embeddings are multi-vector tensors, not one dense vector per page.
  This crate stores exact `.safetensors` bytes plus shape metadata, preserving
  the tensors needed for MaxSim. `pgvector` can be added later for pooled
  prefilter vectors, but should not replace the exact multi-vector storage.

Key files:

- `RustLibraries/vector_store/src/lib.rs`
- `RustLibraries/vector_store/sql/schema.sql`
- `RustLibraries/vector_store/tests/integration.rs`
- `RustLibraries/vector_store/README.md`

Status:

- `cargo test` passes.
- Integration test skips real DB I/O unless `VECTOR_STORE_DATABASE_URL` is set.

## P&ID Extraction Reality Check

Current observations on a complex multi-page P&ID:

- MinerU is useful for title blocks, tables, legends, and some image-analysis
  descriptions. It is not an authoritative graph extractor.
- Qwen3-VL can describe visible regions but hallucinated huge sequential tag
  chains on dense diagrams.
- PaddleOCR-VL direct vLLM also hallucinated a huge sequential tag chain on
  full-page page 3.
- For actual P&ID connection/flow extraction, the next architecture should be:
  1. Rasterize high DPI.
  2. Tile pages into overlapping regions.
  3. OCR exact visible tags per region with strict prompts.
  4. Cross-check tags against extracted tables/title blocks.
  5. Add geometry/vector analysis for lines, arrows, symbols, and endpoints.
  6. Only then ask a VLM to explain local connections with the OCR/geometry
     facts provided as context.

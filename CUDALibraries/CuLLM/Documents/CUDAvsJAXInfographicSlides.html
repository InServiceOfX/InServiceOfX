WMMA is hand-written too — CUDA's tensor-core intrinsics, not a library call. But it's not just a bigger tile: WMMA's fragments are opaque, so the running accumulator can't be rescaled in registers and has to round-trip through shared memory every tile. CUTLASS/CuTe's coordinate tensors remove exactly that cost, worth ~2.7× on their own. CUTLASS/CuTe itself isn't attention-specific — it's NVIDIA's general-purpose library for hand-building GEMM-class kernels, useful any time an application needs a custom kernel and no vendor library covers it.

Same FLOPs, different bytes

N = 2048, batch·heads = 96, d = 64 — the exact shape used throughout this deck.

FLOPs — the arithmetic itself

Identical either way

FLOPs = 4 · (batch·heads) · N² · d
= 4 · 96 · 2048² · 64 ≈ 103 GFLOP
Same QKᵀ and PV multiply-adds — standard and Flash tile the same math differently. This number doesn't change.
Bytes — what has to move

Standard vs. Flash, ~8× apart

Standard: writes the full N×N score matrix → 1.61 GB
Flash: never builds it → just Q/K/V/O → 0.20 GB
Same FLOPs, 8× less memory traffic.
Arithmetic Intensity = FLOPs ÷ bytes moved — how much compute you get per byte loaded. Standard: 103 GFLOP ÷ 1.61 GB ≈ 64 FLOP/byte. Flash: 103 GFLOP ÷ 0.20 GB ≈ 512 FLOP/byte. The Roofline Model says achievable speed ≤ min(peak compute, Arithmetic Intensity × memory bandwidth) — higher intensity pushes you toward the compute ceiling instead of the memory one. At N=4096 this isn't just slower, it's why the 6.44 GB score matrix doesn't fit on a 12 GB card at all: bytes, not FLOPs, decide whether it runs.

Same algorithm, different instruction

Arithmetic intensity explains the memory story. This is the compute story — and the actual CUDA-vs-JAX answer.

FLOP/s — throughput, not a hardware constant

What one instruction actually does

FLOP/s = FLOPs ÷ time — measured, not a spec-sheet number.
One scalar CUDA-core FMA: 2 FLOPs, one lane, one cycle.
One 16×16×16 tensor-core MMA: 16·16·16·2 = 8,192 FLOPs, one warp, one instruction.
CUDA C++ vs. JAX, hand-written

The engine win doesn't travel languages

JAX FA-2 (lax loops): same tiling, same 512 FLOP/byte win as CUDA — 74.4 ms.
CUDA CUTLASS/CuTe: same algorithm, tensor-core instructions issued directly — 19.0 ms.
Identical arithmetic intensity; 3.9× apart on engine access alone.
The algorithm win — streaming tiles instead of materializing N² — is yours in either language; JAX's FA-2 gets the same 8× arithmetic intensity CUDA does. The engine win — issuing tensor-core instructions directly instead of through a compiler's dispatch — is why hand-written CUDA still leads hand-written JAX for the identical algorithm. That's the real answer to "CUDA C++ or JAX for a custom kernel": both get you the memory win; only one gets you the rest of the way to the hardware.
